# 📝 네이버 블로그 포스팅 매니저 & AI 사진 모자이크 스튜디오

네이버 블로그(Naver Blog) 운영자를 위한 **카테고리별 Markdown 원본 관리**, **AI 얼굴 자동 모자이크**, **네이버 스마트에디터 원클릭 복사**, **GitHub 영구 백업** 통합 웹 도구입니다.

---

## 🌟 핵심 기능

### 1. 📂 카테고리별 Markdown (.md) 원본 포스트 관리
- `posts/parenting/`: 육아 관련 마크다운 원본 글
- `posts/it/`: IT/테크 관련 마크다운 원본 글
- `posts/travel/`: 여행 관련 마크다운 원본 글
- 카테고리별 필터링, 새 글 작성, Markdown 실시간 수정 및 미리보기 지원.

### 2. 🐰 토끼 얼굴 모자이크 스튜디오 (AI 얼굴 모자이크 탭)
- **사진 + 영상** 둘 다 지원. 브라우저 내 AI(face-api.js)가 얼굴을 **자동 감지**해서 토끼
  스티커로 가리거나(기본), 기존처럼 픽셀 블러로 처리 — 둘 중 선택 가능.
- 영상은 프레임마다 얼굴 위치를 따라가며 토끼를 씌우고, **오디오 트랙 없이 저장돼 자동으로
  무음** 처리됨.
- 영상 자동 인식이 못 미더울 땐 **"수동으로 프레임 확인하며 배치"** 모드로 전환해서 직접
  프레임을 확인하며 토끼를 놓을 수 있음. 0.1초/0.5초 단위로 이동하면서 영상 위를 클릭해
  토끼를 놓거나(다시 클릭하면 제거) 크기를 조절하고, "저장" 버튼 없이 클릭하는 즉시 그
  시점(키프레임)에 반영됨 — 놓은 위치는 얼굴을 다시 옮겨서 새로 클릭하기 전까지 그대로
  유지되고(보간 없이 고정), 저장된 시점들은 칩 목록으로 보여서 클릭해 다시 찾아가거나 삭제
  가능. 얼굴 인식 모델이 전혀 필요 없어서 face-api.js CDN이 막혀있어도 그대로 쓸 수 있음.
- 100% 브라우저 온디바이스(Client-side) 처리로 사진/영상이 어디에도 업로드되지 않음.
- 모바일 브라우저에서도 그대로 사용 가능 (반응형 레이아웃).
- 사진은 **여러 장 한 번에** 업로드해서 순서대로 자동 처리 (영상은 한 번에 하나씩 — 여러 개
  선택하면 큐에 담아 순서대로 처리). 자동 인식이 놓친 얼굴은 "얼굴 직접 추가"로 사진을 눌러서
  보완 가능, 잘못 눌렀으면 되돌리기 지원.
- 사진마다 **설명 메모**를 적어두면(뭐가 찍혔는지 한두 줄), Claude가 사진을 직접 보지 않고도
  그 메모만으로 포스트 글을 쓸 수 있어 토큰을 크게 아낀다. 메모는 채팅창에 붙여넣기용으로
  전체 복사하거나, "GitHub 백업 관리" 탭에서 저장소에 바로 올릴 수도 있음 (아래 4번 참고).
- 처리된 사진/영상 **1-Click 다운로드** (개별 또는 전체 일괄).
- 모든 처리 결과(사진 + 영상 둘 다) 오른쪽 아래 구석에 **"대왕토끼" 표식**을 작게 새겨서
  불펌(무단 도용) 방지용 마크로 남긴다. 반투명 처리라 사진 감상에는 거슬리지 않음.
- 같은 기능을 커맨드라인에서 폴더째 일괄 처리하고 싶다면 `automation/rabbit-mosaic/`
  (Python 스크립트)를 참고하세요.
- **"GitHub 백업 관리" 탭에서 넘어오기**: 설명 메모를 먼저 올린 뒤(아래 4번) "이어서 토끼
  모자이크 처리하기" 버튼을 누르면, 같은 사진들을 다시 선택할 필요 없이 여기로 바로 넘어와서
  자동으로 얼굴 인식이 시작된다 — 메타정보 먼저 남기고 → 업로드 → 바로 이어서 모자이크,
  한 흐름으로 이어짐.

### 3. 📋 네이버 스마트에디터 ONE 원클릭 변환기
- 마크다운으로 작성된 글을 네이버 스마트에디터 전용 서식(Maru Buri 폰트, 인용구, 본문 스타일, 표 등)으로 변환.

### 4. 🐙 GitHub 백업 및 버전 관리 ("GitHub 백업 관리" 탭)
- 작성한 포스트 원본(`.md`)과 모자이크 완료된 안전한 사진들을 GitHub 저장소에 밀어넣어 평생 안전하게 보존.
- **설명 메모 + 사진 GitHub 업로드**: 원본이든 토끼 모자이크 스튜디오에서 처리해서
  다운로드해둔 것이든, 사진들을 여기서 선택하고 사진마다 설명(또는 모자이크 스튜디오에서
  복사해온 설명 텍스트를 한 번에 붙여넣기)을 채운다. **기본은 사진 자체는 올리지 않고
  설명 메모(`captions.md`)만 저장소에 커밋** — 얼굴이 그대로 보이는 원본을 캡션 붙이기용으로
  올려도 저장소에는 사진이 절대 올라가지 않는다. 모자이크 처리를 끝낸 뒤 "사진도 같이
  올리기"를 켜고 다시 올리면 그때 실제 파일이 `public/images/<폴더>/`에 커밋됨. Claude는
  그 폴더의 설명만 읽고도 글을 쓸 수 있음. 얼굴 인식/모자이크 로직과는 완전히 분리된 도구지만,
  설명 메모 업로드가 끝나면 뜨는 **"이어서 토끼 모자이크 처리하기"** 버튼으로 같은 사진들을
  다시 선택할 필요 없이 바로 모자이크 스튜디오로 넘겨서 이어서 작업할 수 있다(위 2번 참고) —
  메타정보를 먼저 남기고, 업로드하고, 바로 이어서 얼굴을 가리는 흐름을 한 번에 잇기 위함.
  토큰은 브라우저 localStorage에만 저장되고 api.github.com으로 바로 전송됨 — **이 저장소
  하나에만 Contents 읽기/쓰기 권한을
  준 fine-grained 토큰**을 만들어 쓰길 권장(일반 `repo` 스코프 전체 토큰은 계정 전체에 쓰기
  권한을 주므로 피할 것). 공용 기기에서는 사용 후 토큰 입력란 옆 X 버튼으로 지우기.
- **AI로 사진 설명 자동 생성**: 설명을 직접 타이핑하지 않아도 AI가 사진을 분석해서 자동으로
  캡션을 채워준다(개별 사진마다 다시 생성하는 버튼도 있음). 두 가지 모드 중 선택 가능:
  - **무료 (기본값)**: transformers.js로 작은 이미지 분류 모델을 브라우저 안에서 직접 돌린다
    — API 키도, 서버 호출도, 과금도 전혀 없다. 문장형 캡션 대신 사진에 뭐가 있을 것 같은지
    태그(라벨) 목록을 뽑아서 이어붙인다 — 문장보다 정보는 거칠지만 Claude가 그 태그만 보고도
    글을 쓰는 데는 충분하다. 처음 시도했던 문장형 캡셔닝 모델(인코더+디코더 두 세션을 동시에
    돌리는 방식)은 실기기(안드로이드)에서 메모리 부족으로 브라우저 탭이 죽는 문제가 반복
    확인돼서, 세션이 하나뿐인 훨씬 가벼운 분류 모델로 바꿨다. 최초 1회만 모델 파일(10MB 안팎)을
    HuggingFace Hub에서 내려받아 브라우저 캐시에 저장하고, 그 다음부터는 오프라인에서도 즉시
    동작한다.
  - **Claude API (유료, 고품질)**: Anthropic API 키를 넣어두면 사진을 선택하는 순간 Claude
    (비전)가 사진을 분석해서 더 정확한 한국어 문장 설명을 만들어준다. 브라우저에서
    api.anthropic.com으로 직접 호출되므로 Claude Code 세션 토큰과는 무관하게 처리되고,
    사용한 만큼 그 API 키의 Anthropic 계정에 소액 과금된다. 키는 GitHub 토큰과 마찬가지로
    브라우저 localStorage에만 저장.
  - 특히 무료(태그) 모드는 문장이 아니라 거친 영어 태그만 나와서 정보가 부족할 수 있다 —
    그래서 AI 태그 칸 밑에 **"내가 직접 추가 설명"** 칸이 사진마다 따로 있다. 여기에 장소·
    상황 등을 직접 적어두면 AI 태그와 함께 `captions.md`에 같이 커밋된다(선택 사항, 비워둬도
    됨).
- **촬영 시각도 메타정보로 같이 올라감**: 사진을 선택하는 즉시 각 파일의 EXIF에서 실제 촬영
  시각을 읽어와 파일명 옆에 표시하고(초록 글씨 = 실제 EXIF 값, 회색 "(추정)" = EXIF가 없어서
  파일 수정 시각으로 대체한 값), `captions.md`에도 사진마다 같이 기록된다. 여러 장을 한꺼번에
  올리면 촬영 시각순으로 자동 정렬해서 저장하므로, Claude가 그 순서만 보고도 그날 시간대별
  흐름(오전엔 뭘 하고 오후엔 뭘 했는지)에 맞게 글을 쓸 수 있다. 서버 호출 없이 브라우저에서
  파일 바이트만 읽어서 처리(EXIF 파서를 직접 구현, 외부 라이브러리 없음).

## 🚀 시작하기 및 로컬 실행

### 패키지 설치 및 개발 서버 실행
```bash
npm install
npm run dev
```
브라우저에서 `http://localhost:5173`으로 접속하여 포스팅 헬퍼 및 모자이크 스튜디오를 바로 사용할 수 있습니다.

### 📱 휴대폰 등 다른 기기에서 접속하기 (같은 Wi-Fi 안에서)
GitHub Pages 배포를 기다릴 필요 없이, 컴퓨터에서 로컬 서버를 띄우고 **같은 Wi-Fi에 연결된
휴대폰 브라우저**로 바로 접속해서 쓸 수 있습니다.

```bash
npm run dev:lan
```
실행하면 터미널에 이렇게 두 줄이 뜹니다:
```
➜  Local:   http://localhost:5173/
➜  Network: http://192.168.x.x:5173/     ← 이 주소를 휴대폰 브라우저에 입력
```
`Network:` 뒤에 나오는 주소를 휴대폰(또는 같은 네트워크의 다른 기기) 브라우저에 그대로
입력하면 됩니다. 컴퓨터 방화벽이 막고 있다면 5173 포트를 허용해주세요. 컴퓨터에서 서버를
끄면(`Ctrl+C`) 휴대폰에서도 더 이상 접속되지 않습니다 — 외부에 공개로 노출되는 게 아니라
같은 사설 네트워크 안에서만 열리는 주소입니다.
